# London School Selector — Application Documentation

**Last updated:** 2026-03-01
**Status:** Streamlit app (Steps 1–5) fully functional; static reference site live on GitHub Pages.

## 1. What This Project Is

Two separate but related tools sharing the same codebase and SQLite database:

### 1a. Static Reference Site
A self-contained HTML file (`report.html`) deployed on GitHub Pages:
**https://qiaohong.github.io/london_school_stats/report.html**

Seven tabs: Primary (KS2), Secondary (KS4), Sixth Form (KS5), Boroughs, Compare Schools, Nearby Schools, Appendix.
Generated by `generate_report.py`. All data is embedded in the HTML at build time. No server required.

### 1b. Interactive Streamlit App
A five-step wizard (`app.py`) that guides a parent from "I work in EC2A" to "here are 15 schools near Haringey with crime and house price context, and a Rightmove link."

Run locally:
```bash
venv_app/bin/streamlit run app.py --server.port 8501
```

## 3. Database (`schools.db`)

Built by running `load_data.py` then `compute_metrics.py` on raw DfE CSV downloads.

### Tables

| Table | Rows | Description |
|---|---|---|
| `schools` | 9,308 | Raw DfE school info — 3 rows per URN (one per academic year 2022–23, 2023–24, 2024–25). Contains Ofsted ratings, school characteristics, postcode, gender, admissions policy. |
| `metrics_ks2` | 1,889 | One row per London primary school, latest available year. Composite score + all KS2 metrics. |
| `metrics_ks4` | 907 | One row per London secondary school, latest available year. Composite score + all KS4 metrics. |
| `metrics_ks5` | 562 | One row per London sixth form, latest available year. Composite score + all KS5 metrics. |
| `metrics_la` | 99 | Borough-level averages, one row per borough × phase (33 boroughs × 3 phases). |
| `metrics_type` | 13 | School-type-level averages (Academy, Maintained, etc.). |
| `raw_*` | various | Unprocessed DfE files loaded verbatim for reference. |

### Key columns shared across `metrics_ks*` tables

| Column | Description |
|---|---|
| `URN` | Unique Reference Number — DfE's primary key for schools |
| `SCHNAME` | School name |
| `LANAME` | Local Authority name (e.g. "Haringey") |
| `LA` | LA integer code (e.g. 206 for Haringey) |
| `POSTCODE` | School's registered postcode |
| `MINORGROUP` | Broad school type: Academy / Maintained school / College / Independent school / Special school |
| `GENDER` | Boys / Girls / Mixed |
| `ADMPOL` | Admissions policy: Selective / Non-selective / Not applicable |
| `RELCHAR` | Religious character (raw DfE value — many variants, see `FAITH_GROUPS` in `db.py` for grouping) |
| `composite_score` | 0–100 score computed by `compute_metrics.py` (see Section 5) |
| `absence_pct` | Overall absence percentage |

### Ofsted join

Ofsted data (`OFSTEDRATING`, `OFSTEDLASTINSP`) lives in the `schools` table, not the `metrics_*` tables. The `schools` table has 3 rows per URN (one per year). The DB query in `utils/db.py` joins with a subquery:

```sql
LEFT JOIN (
  SELECT URN, OFSTEDRATING, OFSTEDLASTINSP
  FROM schools
  WHERE OFSTEDRATING IS NOT NULL
  GROUP BY URN
  HAVING MAX(academic_year)
) s ON m.URN = s.URN
```

This selects the most recent Ofsted rating available per school. Coverage: ~96% of schools in scope (2,688 / ~2,800). **Source: DfE school information file for 2022–23** — the 2023–24 and 2024–25 DfE files dropped the Ofsted columns, so ratings may lag actual inspection dates.

## 4. Data Sources — Full Inventory

### 4a. School Performance Data

| Data point | Source | Coverage | Recency |
|---|---|---|---|
| KS2 attainment & progress | DfE `ks2final.csv` / `ks2revised.csv` | 1,889 London primaries | 2024–25 (progress from 2023–24 onwards only — DfE suspended KS1-referenced progress in 2022–23) |
| KS4 attainment & Progress 8 | DfE `ks4final.csv` / `ks4revised.csv` | 907 London secondaries | 2024–25 (P8 for some schools still shows 2023–24) |
| KS5 A-level value added | DfE `ks5final.csv` / `ks5revised.csv` | 562 London sixth forms | 2024–25 |
| Absence | DfE `abs.csv` | ~2,800 schools | 2023–24 (no 2024–25 absence data released yet as of Mar 2026) |
| Destinations | DfE `ks4_pupdest.csv`, `ks5_studest.csv` | ~2,400 schools | 2023–24 (16-month lag — 2024–25 destinations not yet published) |
| School information (type, gender, admissions, Ofsted) | DfE `school_information.csv` | All schools | Ofsted from 2022–23 file (later files dropped these columns) |

**Download source:** https://www.compare-school-performance.service.gov.uk/download-data
All data covers England. `load_data.py` filters to London LAs only.

### 4b. Ofsted Ratings

- **Source:** DfE school information file (academic year 2022–23)
- **Values in DB:** Outstanding, Good, Requires improvement, Inadequate, Special Measures, Serious Weaknesses
- **Display grouping:** Special Measures and Serious Weaknesses are shown as "Inadequate" in the UI
- **Limitation:** Reflects the rating at the time of the 2022–23 DfE file. Schools inspected or re-graded since then will show stale ratings. Approximately 4% of schools in scope have no Ofsted record.

### 4c. Postcode Geocoding

- **Service:** [postcodes.io](https://postcodes.io) — free, no API key
- **Used for:** (1) Geocoding school postcodes (batch POST, up to 100 at a time) for crime data lookups and the map in the static site; (2) Resolving the user's work postcode to lat/lng at runtime
- **Fallback:** If full postcode fails, tries outward code (e.g. `N8` from `N8 9DP`)
- **Coverage:** 2,526 / 2,538 school postcodes resolved at static site build time. Runtime: same fallback logic.
- **What the coordinate represents:** The centroid of the postcode unit — typically a point near the middle of the postcode's delivery area, not always the school's exact entrance.

### 4d. Commute Time Estimates

- **Source:** No live API. Entirely heuristic, based on a manually curated static file: `data/la_commute_profile.json`
- **What each LA profile contains:** centroid lat/lng (approximate geographic centre of the borough), TfL zone range, dominant transit type (tube / DLR / overground / rail), list of main lines, inner London flag, character description
- **LA centroid definition:** Manually estimated approximate centre of each borough's residential area. **Not** the borough's administrative centroid — biased slightly toward where most residents live and where transit access is strongest.
- **Calculation:**
  1. Resolve work postcode → lat/lng (via postcodes.io)
  2. Compute straight-line (haversine) distance from work lat/lng to each LA's centroid lat/lng
  3. `estimated_commute = 10 min (base transfer) + distance_km / speed_km_per_min`
  4. Speed: tube = 0.38 km/min (~23 km/h), DLR = 0.34, overground = 0.30, rail = 0.28
  5. Apply a variance factor to get a range: tube (×0.80 to ×1.25), rail (×0.70 to ×1.40)
- **Filter logic:** An LA passes if its estimated minimum commute ≤ (user limit + flex buffer). Results sorted by mid-point estimate ascending.
- **Important caveats:**
  - Does not model actual transit routes, timetables, or walking legs
  - Does not account for rush-hour congestion or service frequency
  - Straight-line distance to LA centroid is a coarse proxy — does not reflect which part of the borough a specific school is in
  - Inner boroughs with multiple tube lines consistently score well even if the work postcode is poorly connected to them
  - The model works better for city-centre work locations than suburban ones

### 4e. Crime Data

- **Source:** [data.police.uk](https://data.police.uk) — free, no API key required
- **Endpoint:** `GET /api/crimes-street/all-crime?lat={lat}&lng={lng}&date={YYYY-MM}`
- **What it returns:** All recorded crimes reported to Metropolitan Police (and City of London Police) within approximately 1 mile of the given point, for the specified month
- **Centroid definition:** The **school's postcode centroid** (lat/lng from postcodes.io). This is the school's location, not the user's home or the admission catchment centre. Every school gets its own API call with its own coordinates.
- **Radius:** ~1 mile. This is fixed by the API when using lat/lng parameters — it cannot be configured. The only way to change it is to POST a custom polygon instead, which is not implemented.
- **Date:** The most recent available month, determined at runtime by calling `/api/crimes-street-dates` (returns descending list; first item = latest). As of March 2026, data runs up to approximately January 2026.
- **Caching:** Results are stored in `st.session_state` for the duration of the user session. Re-loading Step 4 does not re-fetch.
- **Crime level thresholds (per month, 1-mile radius):**
  - Low: < 400
  - Moderate: 400–699
  - High: 700–999
  - Very high: ≥ 1,000
- **Known limitations:**
  - The 1-mile radius is much larger than most schools' admission catchments. Schools in dense urban areas (e.g. Tower Hamlets, Islington) will almost always show higher counts than suburban schools, partly due to geography rather than neighbourhood character
  - Schools sharing the same postcode return nearly identical counts
  - Does not reflect crime trends — only the single most recent month
  - Crime recording practices vary between boroughs; comparisons across boroughs should be treated cautiously
  - Some crime types (e.g. shoplifting, theft from person) are more prevalent in commercial high streets, which may inflate counts for schools near town centres

### 4f. House Prices

- **Source:** `data/la_house_prices.json` — **static file, manually compiled**
- **Values:** Approximate 2024 median sale price per London borough, based on Land Registry UK House Price Index public data
- **Granularity:** Borough (LA) level — all schools in the same borough show the same figure
- **Limitation:** Does not reflect postcode-level variation within a borough, which can be very large (e.g. Haringey has both Muswell Hill at £900k+ and Tottenham at £400k). Treat as a rough orientation, not a property valuation.
- **Update cadence:** Static — requires manual update when new data is published.

### 4g. Admissions Data

- **Source:** `data/la_admissions_urls.json` — manually compiled directory of 33 London LAs' admissions pages, based on a Gemini-generated research document (`gemini_london_admission_data.md`)
- **What is shown in the app:** A link button to each LA's admissions outcome page. No cut-off distances are stored in the app yet — the user must visit the LA page themselves.
- **Admission cut-off distance:** Not yet programmatically scraped. Planned for a future phase (see `plan_7_deep_dive.md`). Cut-off distances vary significantly year to year.
- **Key facts about London admissions:**
  - Most London boroughs measure distance **straight-line (as the crow flies)** from home address to school gate — not road distance or walking distance
  - Published cut-off distances are the "last child offered on National Offer Day" — actual final distances stretch further as families decline places
  - Some schools use banding (Greenwich, Tower Hamlets, Wandsworth) — cut-off distances are calculated per band
  - National Offer Day: 1 March (secondary), 16 April (primary)

### 4h. Rightmove Property Search

- **Integration type:** URL-only — the app builds a search URL and opens it in a new browser tab. No scraping, no API calls.
- **URL format:** `https://www.rightmove.co.uk/property-for-sale/in-{outcode}.html?radius={miles}&sortType=6`
- **Outcode:** Extracted from the school's postcode (first part, e.g. `N8` from `N8 9DP`)
- **Radius:** Snapped to nearest Rightmove-supported value (0.25, 0.5, 1.0, 1.5, 2.0, 3.0, 5.0 miles). Default: 0.5 miles. When admission cut-off distance is available, uses that × 1.2 (20% buffer), converted from km to miles.
- **Note:** Rightmove's internal location identifier API (`/api/typeAhead/uknoauth`) returned 404 when tested. The outcode approach is the reliable fallback and sufficiently precise for this use case.
- **User controls in app:** Listing type (sale/rent), max price, min bedrooms.

## 5. Composite Score Methodology

Scores are computed by `compute_metrics.py` and stored in `schools.db`. Each metric is **percentile-ranked within London** (0 = lowest-performing school in London, 100 = highest). Missing values are imputed at 50 (London median — neutral). Weights are judgement calls.

| Phase | Metric | Weight |
|---|---|---|
| **KS2** | Average KS2 progress | 40% |
| | % achieving expected standard in RWM | 30% |
| | Absence (inverted — lower absence = higher score) | 15% |
| | % achieving higher standard in RWM | 15% |
| **KS4** | Progress 8 | 35% |
| | % achieving grade 5+ in English & Maths | 25% |
| | Absence (inverted) | 15% |
| | Destinations to education | 15% |
| | EBacc 4+ | 10% |
| **KS5** | A-level value added | 40% |
| | % achieving AAB in facilitating subjects | 25% |
| | HE destinations | 25% |
| | Absence (inverted) | 10% |

**Composite score = 50 means a school is at the London median.** A score of 75 means the school outperforms 75% of London schools on that phase's weighted metric set.

## 6. Child Age → Year Group → School Phase Logic

Implemented in `utils/age_stage.py`.

**UK school year:** starts 1 September. A child's year group is determined by their age on 1 September of the current academic year.

```
age_at_sept = current_academic_year_start - birth_year
             (subtract 1 if born September–December, as they're younger in that cohort)
year_group  = age_at_sept - 4   (Reception = age 4–5, Year 1 = age 5–6, ...)
```

**Phase mapping:**
- Year Group −1: Nursery
- Year Group 0–6: Primary (KS1/KS2)
- Year Group 7–11: Secondary (KS3/KS4)
- Year Group 12–13: Sixth Form (KS5)

**Look-ahead:** The app considers the child's current year group plus the next 3 years. If a child is currently in Year 5, the app surfaces both Primary and Secondary (Year 7 is 2 years away). This drives which `metrics_ks*` tables are queried.

## 7. The Five App Steps

### Step 1 — Input
User provides: work postcode, commute limit (minutes), flexibility (strict / +20 min), number of children (up to 3), each child's birth month and year.

Live year group and phase preview shown as the user types. Stored in `st.session_state`.

### Step 2 — LA Selection
1. Work postcode resolved to lat/lng via postcodes.io (cached in session)
2. Commute estimated to all 33 LAs (heuristic — see Section 4d)
3. Top 3 recommended LAs shown with rationale (character blurb + line/zone info from profile)
4. All 33 LAs shown as checkboxes (recommended pre-ticked); user can adjust
5. Selected LAs stored as list of LA name strings; converted to integer LA codes for DB queries via `la_name_to_code()`

### Step 3 — School Criteria
Filters: Ofsted rating, include-no-Ofsted checkbox, school type (MINORGROUP), admissions policy (ADMPOL), gender (GENDER), religious character (RELCHAR — grouped into 8 display categories), composite score floor.

All filter values stored in `st.session_state.criteria` dict.

### Step 4 — Shortlist
1. `query_schools()` called per ks_key (ks2/ks4/ks5) with all criteria. Results cached per session.
2. All shortlisted school postcodes batch-geocoded (postcodes.io bulk POST)
3. Crime data fetched per school (sequential API calls with progress bar, up to 20 schools). Cached in `st.session_state.neighbourhood_data`.
4. School cards shown, sorted by composite score (default). Each card: name, type, Ofsted badge, score, key metric, absence, house price (static), crime count + level + top categories.
5. "View full details →" button sets `selected_school`, `selected_school_nb`, `selected_ks_key` in session state and navigates to Step 5.

### Step 5 — Deep Dive
- Full performance metrics with London average delta indicators
- Borough comparison (from `metrics_la` table)
- Neighbourhood: full crime category breakdown table, house price
- Admissions: policy, faith character, link to LA's admissions page (from `la_admissions_urls.json`)
- Rightmove: optional filters then link button (outcode-based URL, default 0.5-mile radius)
- "Back to shortlist" (preserves all session state) and "Start over" (clears all session state)

## 8. Known Limitations

| Area | Limitation |
|---|---|
| Commute | Heuristic only — does not use live timetable or routing data. Accuracy degrades for suburban work postcodes or multi-modal journeys. LA centroid is a single point; a school in the far corner of a borough will be significantly mis-estimated. |
| Ofsted | Sourced from 2022–23 DfE file. Schools re-inspected since then show stale ratings. ~4% of schools have no Ofsted record. |
| Absence | No 2024–25 data — uses 2023–24 figures. |
| Progress 8 (KS4) | Some schools still show 2023–24 P8 where 2024–25 not yet published. |
| Destinations | 16-month publication lag — 2024–25 data not yet available. |
| KS2 progress | Only available from 2023–24 onwards (DfE suspended KS1-referenced progress in 2022–23). |
| Crime radius | Fixed ~1 mile around the school's postcode centroid. Cannot be narrowed. Overestimates crime exposure for schools with tight admission catchments. Comparisons across boroughs of different densities are unreliable. |
| House prices | Borough-level only. Intra-borough variation can be very large. Static 2024 data — not updated automatically. |
| Admission cut-offs | No per-school cut-off distance data yet. Planned for future phase. |
| Rightmove radius | Defaults to 0.5 miles regardless of actual admission distance (until cut-off data is added). |
